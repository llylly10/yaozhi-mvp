# 接口 / 数据模型命名一致性核对报告（2026-09-03）

核对范围：`backend/app/models.py`（数据模型）、`backend/app/router.py`（接口）、`frontend/src/api.ts` + `App.tsx`（前端契约）、《实施方案设计 v1.2》第 6 章接口表与数据模型表。
核对方法：全量通读 + 前后端字段交叉比对 + 文档-代码比对。

---

## A 类：代码层命名/契约不一致（含 1 个必现故障）

### A1【P0·功能故障】复测提交流程必现 404
- 后端 `GET /retest/{training_id}` 返回 `retest_id: "rt-" + ts.id`（带前缀）；`POST /retest/{training_id}/submit` 内部 `db.get(TrainingSession, training_id)` 按**裸 UUID** 查询。
- 前端 `finishRetest` 用 `retest.retest_id`（即 `rt-{uuid}`）调 `submitRetest` → `POST /retest/rt-{uuid}/submit` → 后端查不到 `rt-{uuid}` → **404**。
- 全链路无任何剥离 `rt-` 前缀的逻辑。**演示链路（训练答对→复测→提交）必现 404。**
- 建议：统一用裸 UUID 的 `training_id`（路由/返回/前端一致），删除 `retest_id` 前缀产物。

### A2【P1】用户资源路由风格三套并存
- `/users/{user_id}/…`：wrong-book、profile-summary、consent、deletion-receipt
- `/learning-plan/{user_id}`、`/assessment/{user_id}`：无 `/users/` 前缀
- `/mastery/me?user_id=…`：用 query 传 user_id，且 "me" 语义与传参矛盾
- 建议：统一为 `/users/{user_id}/…` 风格（如 `/users/{user_id}/learning-plan`、`/users/{user_id}/assessment`、`/users/{user_id}/mastery`）。

### A3【P1】同概念字段在不同端点命名不一致
- 训练提交返回 `session_state`（`submit_training`），诊断查询返回 `state`（`get_diagnosis`）——同一会话状态两个字段名。
- 复测提交返回 `mastery_state: None`（永远占位空值）——无用字段，且命名暗示有值，应移除或返回真实掌握状态。

### A4【P2】域（domain）返回结构不一致
- `learning_plan` 任务：`domain_id`（id）+ `domain`（名称）。
- `assessment` 聚合：只有 `domain`（名称），无 `domain_id`。
- `profile-summary` 热力图：只有 `domain`（名称）。
- 前端若需按域跳转，仅 learning_plan 能拿到 id；建议三处统一带 `domain_id` + `domain`。

## C 类：术语/语义一致性

### C1【P2】`Attempt.confidence` vs `DiagnosisSession.evidence_level`
- 两者值域都是「高/中/低」，但**语义不同**：`confidence` 是学生作答时的自评信心（输入），`evidence_level` 是诊断结论的证据强度（输出）。
- MEMORY 记录的"置信度→证据等级术语迁移"若指合并两者，建议**不要合并**（概念不同）；应在文档中明确区分并保留 `confidence` 为学生输入字段。

### C2【P2】`chapter_ref` 同名异义
- `DiagnosticDomain.chapter_ref`：诊断域对应的章节（业务语义）。
- `TikuQuestion.chapter_ref`：题库题映射的章节（可含 `CH8,CH9` 并列）。
- 两者同名但含义、取值规则不同，文档需加注释区分，避免混淆。

### C3【P3】计划态残留字段
- `FollowupTurn.judge_method` 枚举含 `model`（W3 才有真实模型判定）；`DiagnosisEvidence.evidence_type` 含 `知识库切片`（知识库未接）——演示不会出现，属计划态占位，保留即可。
