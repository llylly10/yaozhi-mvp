## 4. 红线话术

### 必须主动说（这是加分项，不是自曝其短）

- 比赛演示阶段 = **Mock 引擎 + SQLite + 题目绑定解析**；PostgreSQL/pgvector、真实模型接入、RAG 均为**下一阶段计划态**。
- 种子内容（10 题 / 追问节点 / 错因目录）为**技术起草，须经真实药理专业人员审核后**才能进入学生试点。
- 题库 786 题已完成章节映射（35 章），其中 **63 道跨章节交叉题保留并列、待顾问裁决**，未擅自自动消解。
- 引用用于追溯依据，**有引用 ≠ 答案一定正确**。
- 任一关键错因类别召回率为 0，或出现严重药理事实错误，系统不得进入真实试点。

### 绝不能说

- ❌「数据不出校」与「调用外部模型 API」并存 —— 二者矛盾。正确说法：完整作答记录与画像保存在校内/学校批准的环境，调用外部模型只发送**去标识化的最小必要内容**。
- ❌「AI 代替药理顾问 / 代替法务」—— 二者是真实试点的**前置条件**。
- ❌「完整知识图谱」—— MVP 只有结构化知识关系。
- ❌「保证稳定 / 保证事实正确」。
- ❌ 任何真实试点效果数字 —— 尚未开展试点，不得虚构。

## 5. 翻车预案

| 现象 | 原因 | 30 秒处置 |
|---|---|---|
| 前端白屏 | 后端没起来 / 端口被占 | 看后端窗口；`curl 127.0.0.1:8000/healthz`；按第 0 节清端口重起 |
| 页面提示「数据不存在或已被重置」 | 有人中途按了复位 | 刷新页面重新注册（邀请码 DEMO2026），从①重走 |
| 答错后不出诊断卡 | 该题未被判为错 / 会话状态未 diagnosed / **选中了题库 T 原题**（无错因标注 → 只给解析反馈卡，属预期设计） | 换一道**带错因标注**的题（题目列表带章名的多为题库原题，种子标注题集中在 M 受体药域）重答；确认选的是错误选项 |
| 训练页 409「会话状态…不能开始训练」 | 诊断未完成就点训练 | 退回诊断卡，等 state=diagnosed 再进 |
| 复测 404 | training_id 传错 | 用冒烟脚本第 13 步的 training_id；接口已统一为裸 UUID，勿加 `rt-` 前缀 |
| 接口报 500 | 数据行异常（如写入了非法枚举值） | `curl -X POST /admin/reset-demo` 复位后重跑冒烟 |
| 演示数据被玩脏 | — | 随时 `curl -X POST http://127.0.0.1:8000/admin/reset-demo`，5 秒回到干净种子 |

> 复位后题库资产自动恢复：786 题 / 35 章 / 未映射 0 / 并列 63 / 补章 4 章归位 36 题 / **published 146（A1 131 + B1 15）桥接物化进闭环**，已实测。

## 6. 评委高频追问 · 答法

| 追问 | 答法 |
|---|---|
| 这个诊断是模型算出来的吗？ | 演示阶段是规则 + Mock 引擎，保证可复现；真实模型接入是下一阶段。诊断过程走固定评测集检查。 |
| 错因只有四类，够吗？ | 四类是一级分类，下设二级错因；分类体系本身须由药理顾问确认。 |
| 追问为什么不自动发起？ | 需求变更：答错直接出卡，追问降级为卡上可选入口（can_refine），完成后跳回诊断卡——避免打断。 |
| 掌握度怎么算的？ | MVP 用规则状态机。BKT 参数拟合需 250 人×6 次/技能，15–30 人试点规模不满足，故不硬上。 |
| 会做 LoRA 微调吗？ | MVP 明确不做，Post-MVP 按六项门槛后再评估。 |
| 内容合规怎么保证？ | 正式题目/解析/知识关系须真实药理人员审核；教学资源须完成公开来源或书面授权登记；演示只用虚构或去标识化数据。 |
| 786 题的章节标注从哪来？ | 题库原文无显式章节标注，靠启发式映射 + 人工抽查；已修正 4 题疑似错误，补 4 个大纲缺章，63 道交叉题保留并列待顾问裁决。 |
